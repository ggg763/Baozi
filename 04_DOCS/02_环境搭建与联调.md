# 环境搭建与联调

按 **PC → ESP32 → TD1601 → 联调** 的顺序做。每一步都有"该看到什么"。

---

## 1. PC 端

### 1.1 基础环境

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10/11 | 代码里对 Windows 串口行为（PermissionError 13）有专门处理 |
| Python | **3.11 ~ 3.13** | 不要用 3.14：`webrtcvad` 等 C 扩展没有对应 wheel |
| 内存 | ≥ 8 GB | 3B 模型常驻约 3 GB |
| 磁盘 | ≥ 15 GB | 依赖（torch）+ ASR 模型（900 MB）+ Ollama 模型（3~5 GB） |

```bash
cd 01_PC/pc_baozi
python -m venv .venv
.venv\Scripts\activate
```

### 1.2 依赖分三层装

**A. 最小集**（够跑离线自测与模拟链路，约 50 MB）

```bash
pip install numpy openai pyserial edge-tts miniaudio requests pillow pypinyin
```

**B. 完整集**（语音识别 + 视觉 + 后端）

```bash
pip install -r requirements.txt
```

**C. GPU 版 torch**（可选，但要显卡就必须单独装）

pypi 上 Windows 的 `torch` 是 **CPU 版** —— `torch.version.cuda` 会是 `None`，
装多少次都不会变。必须走 PyTorch 官方源：

```bash
pip install torch==2.11.0+cu128 torchaudio==2.11.0+cu128 ^
  torchvision==0.26.0+cu128 --index-url https://download.pytorch.org/whl/cu128
```

三条约束（2026-10-28 实测）：

- `cu128` 通道最高只到 **torch 2.11.0**；`cu130` 有 2.14，但需要 R580+ 驱动
- 必须同时装 `torchvision 0.26.0+cu128`，否则 ultralytics 报 `requires torch>=2.14`
- 官方源实测 5.4 MB/s，2.5 GB 约 3~4 分钟；**清华镜像的 torch 也是 CPU 版，别用**

验证：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 期望：2.11.0+cu128 True NVIDIA GeForce RTX ...
```

### 1.3 Ollama 模型

```bash
ollama pull qwen2.5:3b      # 对话（约 1.9 GB）
ollama pull qwen3-vl:2b     # 视觉兜底（约 1.9 GB）
```

对应 `config.json`：

```json
"llm_model":    "qwen2.5:3b",
"vision_model": "qwen3-vl:2b"
```

⚠️ **不要用带思维链的模型**（qwen3 系列、deepseek-r1）。它们把 token 花在
内部推理上，`content` 可能返回空，语音助手直接哑掉。代码检测到这种情况会
抛出明确错误，但更省事的做法是直接用 `qwen2.5`。

验证：

```bash
ollama ps                                  # 推理后应显示 100% GPU
curl -s localhost:11434/v1/models | head   # 列出可用模型
```

### 1.4 首次自检

```bash
python selftest.py
```

**该看到**：`84 通过, 2 失败`。那 2 项是代码与测试的规格冲突（见 README 第 6 节），
换成任何机器都是这个结果 —— 如果你的数字不同，说明依赖没装齐。

不接硬件验证整条流水线：

```bash
python server.py --asr-backend mock --llm-backend echo --tts-backend tone
```

**该看到**：`[link] 监听 0.0.0.0:8765，等待 ESP32 连接 ...`，进程不退出即成功
（按 Ctrl+C 结束）。

## 2. ESP32 端

### 2.1 环境

| 项 | 要求 |
|---|---|
| Arduino IDE | 2.x |
| esp32 core | **≥ 3.0.0**（用了 `ESP_I2S` 与 `esp_adc/adc_continuous`，2.x 编不过） |
| 第三方库 | **零**，全部是 core 自带 |

### 2.2 三个必设项

打开 `02_ESP32/esp32_baozi/esp32_baozi.ino`。**文件夹必须叫 `esp32_baozi`**
（Arduino 硬性规定：`.ino` 所在文件夹名必须与文件名一致，否则一打开就报
`sketch must be in a folder named esp32_baozi`）。

| 设置项 | 值 | 不设的后果 |
|---|---|---|
| 开发板 | ESP32S3 Dev Module | — |
| Flash Size | 16MB | 分区表对不上 |
| PSRAM | **OPI PSRAM** | 摄像头初始化失败、播放任务创建失败，喇叭完全不响 |
| Partition Scheme | 16M Flash (3MB APP/9.9MB FATFS) | — |
| USB CDC On Boot | **Enabled** | `Serial` 落到 UART 口，PC 收不到任何帧 |

原始编译参数（Arduino IDE 内部就是这样存的）：

```
esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB
```

### 2.3 现场换 WiFi 只改一处

凭据在 `02_ESP32/esp32_baozi/wifi_secrets.h`（**不入库**，模板 `wifi_secrets.example.h`）：

```c
// wifi_secrets.h
static const char* const WIFI_SSID_LIST[]     = { "现场热点", "备用热点" };
static const char* const WIFI_PASSWORD_LIST[] = { "现场密码", "备用密码" };
#define AP_PASSWORD "自己定一个 ≥8 位"
```

两个数组必须**同长度、同顺序**，否则读到脏内存（现象是连不上或乱连）。
热点个数不用手写，`config.h` 里由 `sizeof` 推出来。

三条硬性约束，违反任何一条都连不上：

- 必须 **2.4 GHz**（ESP32-S3 硬件不支持 5 GHz，iPhone 热点要开"最大兼容性"）
- 必须 **WPA2**（WPA3 兼容性差，报 status=6）
- SSID 用**纯英文**（中文 SSID 实测报 status=6 被对方断开）

### 2.4 不装 Arduino 也能烧

`firmware/` 里是已编译好、实测能出声的固件：

```bash
esptool.py --chip esp32s3 -p COMx -b 921600 write_flash ^
  --flash_mode dio --flash_freq 80m --flash_size 16MB ^
  0x0     firmware/esp32_baozi.ino.bootloader.bin ^
  0x8000  firmware/esp32_baozi.ino.partitions.bin ^
  0x10000 firmware/esp32_baozi.ino.bin
```

烧之前关掉串口监视器，否则报端口占用。烧完按 RST，串口 115200 应看到 WiFi 连接日志。

## 4. 联调顺序

**不要一次全接上再排查**，按下面顺序，每步确认后再进下一步。

### 第 1 步：TD1601 单独上电

该看到：三色自检 → 米黄表情脸；串口打印

```
[app] touch ready
[app] uart ready (UART0 PA18/PA17 @115200, shared with printf)
[app] esp uart ready (UART3 PB18 only ...)
[app] emotion + servo ready
```

点一下屏幕 → `[GEST] TAP @(x,y)`；长按 800 ms → 进卡片层（TODAY 页）。

### 第 2 步：PC 单独跑（不接板）

```bash
python main.py --no-vision --no-td1601 --no-app --transport serial
```

串口打不开时会提示"找不到 ESP32 的串口"并继续等待 —— 这就对了，
说明依赖、模型、配置都通了。

### 第 3 步：ESP32 单独上电

串口 115200 应看到 WiFi 连接日志、`[td] UART2 就绪：TX=GPIO14 -> TD1601 PB18`。

### 第 4 步：PC + ESP32（先不管 TD1601）

```bash
python main.py --no-vision --no-td1601 --no-app
```

**该看到**：

```
[link] 设备上线: esp32s3cam fw/...
[link] 就绪。语音：对着麦克风说话 ...
```

对着麦克风说话 → 有识别文本 → 包子回话（喇叭出声）。

排障要点：

- 打不开串口 → Arduino 串口监视器 / SSCOM 还开着（程序会等 60 秒自动重试）
- 一直"还没收到握手" → USB 线是数据线吗？固件是 USB 模式吗（`USE_USB_LINK`）？
- 有识别但喇叭不响 → 看 `[esp]` 前缀日志里的播放状态

### 第 5 步：接上 TD1601（情感链路）

```bash
python main.py --no-vision --no-app
```

说一句话，TD1601 串口应出现：

```
[esp] cmd: INTENT:CHAT
[st] 0x22 emo=happy    intent=chat     inten=medium
```

同时屏幕上表情变化、舵机摆姿。这一条通了，说明链路 ② 完整。

### 第 6 步：接上习惯/日程（链路 ③）

需要额外一根 USB-TTL 接 TD1601 的 `PA17/PA18`：

```bash
python main.py --no-vision
```

`config.json` 的 `app_board_port` 留空会自动握手识别屏幕串口。
该看到卡片层出现习惯/日程，点格子 → PC 日志出现 `0x90` 打卡回报。

### 第 7 步：视觉

```bash
python main.py
```

问"你看到了什么" → PC 发 `CTRL_CAM_REQ` → ESP32 抓图回传 → YOLO/VL 描述。

排障：8 秒超时不回图，先看有没有 `[esp] [cam] 收到抓图请求` 这行 ——
没有说明请求根本没到固件；有但没后续，是摄像头侧问题（多因 PSRAM 没设成 OPI）。

## 5. 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `sketch must be in a folder named esp32_baozi` | 文件夹名不对 | 改名 |
| 喇叭完全不响 | PSRAM 没设 OPI / 缓冲太大吃光 RAM | 按 2.2 设置 |
| 连不上 WiFi，status=6 | 5 GHz / WPA3 / 中文 SSID | 换 2.4G + WPA2 + 英文 |
| 串口打不开（PermissionError 13） | 监视器占着 | 关掉，程序会等 60 s |
| 包子自问自答 | 喇叭声音被自己麦克风收进去 | `echo_guard_ms` 调大（默认 600） |
| 一句话被切成两段 | VAD 结束门限太灵敏 | `vad_end_ms` 调大 |
| 一句话前半截丢失 | VAD 起始门限太高 | `vad_start_preroll_ms` / `vad_start_threshold_db` 调整 |
| 情绪永不切换 | 模型没按 JSON 输出 | 看日志 `[llm]`；确认用的是 `qwen2.5` 不是 `qwen3` |
| 冷启动前两轮回 "neutral" | `warmup()` 预热不足 | 先说两句废话；或改 `warmup()` |
| 屏幕花屏 / 白块 | 舵机与屏幕 DMA 抢总线 | 确认 `servo_bus_event` 注册（合并版已做） |
| TD1601 编译报 undefined reference | `package.yaml` 漏登记 | 只改 yaml，别只改 `Baozi.mk` |
