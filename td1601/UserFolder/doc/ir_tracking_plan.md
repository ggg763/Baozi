### 0.1 ⚠️ 硬件接线硬要求

> **2026-08-30 现场定案**：模块由**独立稳压电源 3.3V** 供电，与核心板（USB）**已共地**。
> 本节最初按"5V 供电"写的，**5V 灌流假设作废**。

**真正的问题：接线接触不良。** 症状是一组间歇性异常 ——
叠加态 `LR / LC / CR / LCR` 读不到、未遮挡那一路的高电平被拖到 0.8V、
"放一段时间 / 重新接线后自愈"。**重新接好线之后，叠加态全部正常出现**，
说明这一组异常同源，且与几何、光学、固件**都无关**。

**教训**：间歇性故障**先查接线**（杜邦线 / 排针 / 面包板接触电阻），再怀疑几何或固件。
本次就是把接线故障误判成了"探头间距与工作距离不匹配"（见 §1.2 的更正）。

**接线规范（务必照做，否则后面调跟随会被反复折磨）**：

1. **焊接优先**；至少去掉面包板、换短而粗的杜邦线；
2. 供电**星形分三路**（别串成一条链），VCC 与 GND 都要；
3. 每个模块 **VCC–GND 加 100nF + 10µF** 去耦；
4. 稳压电源**限流调到 ≥500mA**；
5. 定型前**烤机 15 分钟**复测（间歇故障不根治会随机复现）。

**电平保护（仍建议做，成本极低）**：TD1601 的 IO 是 **1.8V 域**，模块 3.3V 推挽输出直连
仍有**轻量灌流**（引脚被钳在 ≈2.5V）。加 **DO —1k— 引脚，引脚 —1k— GND**（3.3V → 1.65V）即可。
⚠️ 若模块是**开漏**输出则**不要**加这个下拉（会与内部上拉分压，导致永远读到低）。

## 1. 光学几何 —— 方案成败的第一前提

红外避障模块探测锥半角约 **17°**（标称 35°）。距离 `d` 处视野半径 `r = d·tan17° ≈ 0.31d`。
两路要有方向分辨力，探头间距需 `s ≥ 2r`：

| 目标距离 d | 视野半径 r | 需要间距 s | 3.5" 方屏（边长 ~71mm）能否满足 |
|---|---|---|---|
| 5cm | 15mm | ≥ 31mm | ✅ 轻松 |
| 10cm | 31mm | ≥ 62mm | ⚠️ 临界（71mm 勉强够） |
| 15cm | 46mm | ≥ 93mm | ❌ 不够 |

**结论**：
- 探测距离调近（**5~8cm**）时，屏幕四周的大间距本身就够分辨，不必加套筒；
- 探测距离 >12cm 时必须加**遮光套筒**把半角压到 ±5°：内径 5mm → 套筒长 `2.5/tan5° ≈ 29mm`；
  此时 10cm 处只需间距 ≥18mm，非常宽松。

> ⚠️ **2026-08-30 实测后修订**：上面只看"能不能分辨"是不够的 —— 还需要"能不能**同时触发**（叠加态）"。
> 见下面 §1.1，间距**不是越大越好**，"分辨"与"叠加"对间距的要求方向相反。

### 1.1 ⚠️ 关键修正：间距必须与工作距离匹配（叠加态从哪来）

"叠加态"（两个探头同时触发，如 `L+C` / `C+R` / **`L+R`**）不是可有可无的 —— 见 §1.3。
它的出现条件是**目标同时进入两个探头的视锥**，而两视锥在距离 `d` 处的半宽是 `d·tanθ`：

```
两视锥恰好相切（分界点）： d_crit = s / (2·tanθ)      θ=17° 时  d_crit ≈ 0.82·s
反过来选间距：            s ≈ 2·d·tanθ = 0.61·d
```

| 期望工作距离 d | 匹配的探头间距 s = 0.61·d |
|---|---|
| 5cm | 30mm |
| 8cm | 49mm |
| **10cm** | **61mm** |
| 12cm | 73mm |
| 15cm | 92mm |

| 目标距离与临界距离的关系 | 视锥状态 | 表现 |
|---|---|---|
| `d < d_crit`（比临界近） | 完全分离 | 只能单独触发，**永远没有叠加态** |
| `d ≈ d_crit` | **部分重叠** | 目标居中时两路同时触发、偏向一侧时只触发一路 ✅ **可用工作区** |
| `d > d_crit`（比临界远） | 重叠过多 | 总是一起触发，方向分辨力下降 |

**结论：间距不是越大越好，而是要与目标工作距离匹配。**

### 1.2 现场诊断结论（⚠️ 2026-08-30 更正）

**原判断作废**：初版根据"实测从不出现 LC / CR / LCR"推断"间距与工作距离不匹配、
视锥分离"，并列出"把探头间距缩到 49mm / 30mm"等改机械方案 —— **该结论是错的**。
真实原因是 §0.1 的**接线接触不良**；**重新接线后叠加态全部正常出现**。

**当前实测结论**：

- 三个独立模块 + 屏幕四周等腰三角布局（**L–R ≈ 71mm**）→ **叠加态可达** ✅
- **机械无需任何改动**，可以直接进入跟随固件开发
- §1.1 的几何公式（`d_crit ≈ 0.82·s`、`s ≈ 0.61·d`）**仍然有效，留作参考**：
  将来换探头、改间距、或改工作距离时，用它核对"视锥是否在目标距离上确实相交"。

### 1.3 二维状态表（含叠加态 → **两轴同时动作**）

这才是"同时调节两个轴"的正确形式（上一版 §3 的表是**降级版**，每拍只动一个轴，
仅在实在拿不到叠加态时才退而用之）：

| seen L C R | 判定 | YAW | PITCH |
|---|---|---|---|
| 0 0 0 | 无目标 | —— | ——（按 §5 的丢失分档处理） |
| 1 0 0 | 左 | **左** | —— |
| 0 1 0 | 中上 | —— | **上** |
| 0 0 1 | 右 | **右** | —— |
| **1 1 0** | 左上 | **左** | **上** |
| **0 1 1** | 右上 | **右** | **上** |
| **1 0 1** | **下方**（下面两个都看到、上方的 C 看不到） | —— | **下** |
| 1 1 1 | 很近 / 居中大目标 | —— | —— |

> 其中 **`L+R` = 下方** 是竖直方向唯一的"向下"编码 —— 这就是为什么叠加态不可省。

### 1.4 决定性验证实验

手掌**张开**（尽量大）放在**屏幕正中央**，然后：

1. 从 **5cm 慢慢退到 18cm**，观察是否在某个距离出现 `L+C+R` 或 `L+R`；
2. 在这个距离上，把手**向左偏** → 应变成 `L_ONLY` 或 `L+C`；**向右偏** → `R_ONLY` 或 `C+R`；
3. 手**向上移** → 应变成 `C_ONLY` 或 `L+C`/`C+R`；**向下移** → 应变成 **`L+R`**。

- 出现 `L+R` → ✅ 叠加态可达，把工作距离固定在这个值，按 §1.3 的表写双轴跟随；
- 任何距离都不出现 → ~~间距与可用距离不匹配，按 §1.2 的调整 2 改机械~~（此分支已作废，见 §1.2）。

> **✅ 2026-08-30 实测结果**：**叠加态出现了** —— `LR / LC / CR / LCR` 均可正常打印。
> 此前"任何距离都不出现"是**接线接触不良**造成的；重新接好线后叠加态正常。
> **结论：按 §1.3 的二维状态表写双轴跟随，机械不改。**

## 2. 布局（480×480 屏幕四周，等腰三角形）

```
            [C]           <- 上边中点（比 L/R 高，负责竖直分辨）
     [L]            [R]
   左下角          右下角
```

- **L–R 间距 ≈ 屏幕宽度（~71mm）** → 水平分辨最好的一对
- **C 与 L/R 的竖直间距 ≈ 屏幕高度** → 提供竖直分辨（这正是"C 高于 L/R"的价值）
- ⚠️ **三个探头都要略微前伸出屏幕平面（3~5mm）**，否则屏幕边框会切掉视野的一侧
- ⚠️ **屏幕自身的反射**：不发光时是黑色低反射面，发光时是白色高反射面，红外可能被屏幕反射误触发 ——
  装配后先把屏幕点亮，看三个探头是否被"自己"触发

## 3. 状态解码表（`seen`：1 = 看到目标，即引脚为低）

| seen_L | seen_C | seen_R | 判定 | 期望动作 |
|---|---|---|---|---|
| 0 | 0 | 0 | 无目标 | 保持 → 超时回中 |
| 0 | **1** | 0 | **锁定**（居中、高度适中） | **不动** |
| 0 | 0 | 1 | 偏右 | YAW += step |
| 0 | 1 | 1 | 右前 | YAW += step/2 |
| 1 | 0 | 0 | 偏左 | YAW −= step |
| 1 | 1 | 0 | 左前 | YAW −= step/2 |
| 1 | 0 | 1 / 1 1 1 | 目标很近或很宽 | 不动 |

**竖直（三角布局的价值）**：

| C | L/R | 判定 | 期望动作 |
|---|---|---|---|
| 1 | 0 | 目标偏高 | PITCH += step（抬头追） |
| 0 | 1 | 目标偏低 | PITCH −= step（低头追） |

## 4. 控制律（**不能用 PID** —— IR 只有"有/无"，没有误差幅值）

| 环节 | 做法 | 建议参数 |
|---|---|---|
| 去抖 | 连续 N 次一致才认 | 3 次 × 20ms = 60ms |
| 控制周期 | 每拍最多走一步 | 100ms（舵机响应不了更快） |
| 步长 | 朝误差方向固定步进（爬坡） | YAW 15us/拍、PITCH 10us/拍（先小后大调） |
| 死区 | 锁定态（C_ONLY）不动 | —— |
| 限速 | 每拍只动一步，不跳变 | —— |
| 限位 | `servo_set_pulse()` 自带钳制 | YAW 300~1700、PITCH 800~1600 |
| 目标丢失 | 保持 1s 后回中；或按上次方向搜索一小段 | 1s |

## 5. 验证与推进步骤（含进度）

1. ✅ **三路状态解码验证**（`UserFolder/test/ir_state_test.c`）——
   `L / C / R` 单独状态与叠加态 `LC / CR / LR / LCR` **均可正常出现**；
2. ✅ **接线可靠化** —— 接触不良曾造成一组间歇异常（叠加态读不到、高电平被拖到 0.8V、自愈），见 §0.1；
3. ✅ **YAW 单轴跟随**（`UserFolder/tracking/track_yaw.c`）——
   **2026-08-30 实机验证：效果非常稳定**；限位 `300~1700`（本项目早先实测值）**确认正确**；
   实现要点：5ms 采样 + 60ms 去抖 → 100ms 步进 15us → 死区锁定 → 丢失分档（200ms 保持 / 1s 慢搜 / 超时回中，回中吸附中位避免震荡）；
4. 🟡 **双轴跟随**（`UserFolder/tracking/track_dual.c`）——
   按 §1.3 的二维表把 YAW + PITCH 一起驱动（`C` 看到 → 抬头；**`L+R` → 低头**）；
   **代码完成、已接口化**（`init/step/exit/lost_ms`，可被状态机非阻塞驱动，见 `doc/README.md` §5.3.1）；

5. 🟡 **与情绪状态机联调** —— **方案已定**：把跟随做成状态机的一个「模式」，
   由指令呼起、模式间互斥（天然解决舵机冲突），接口已备好（`doc/README.md` §5.3）。

**单轴基线保留**：`track_yaw.c` 已验证稳定，作为回归基线留着；双轴出问题时可以切回它判断是

## 6. 风险清单

| 风险 | 表现 | 对策 |
|---|---|---|
| **视野重叠**（头号） | 三路总是一起触发，state 在 NONE/LCR 间跳 | 遮光套筒 / 拉大间距 / 调近探测距离 |
| 二值抖动 | 状态在阈值边缘频繁跳变 | 去抖 60ms + 死区 |
| 屏幕反光 / 环境强光 | 无目标却常触发 | 探头前伸、避开强光、必要时加 38kHz 调制型 |
| 深色目标 | 探测距离显著缩短 | 三路电位器调到一致的近距离 |
| **探头装在底座上** | 云台转了但探头没转 → 永远不收敛 | **探头必须随云台转动** |
| 舵机堵转 | 上电顶极限 | 供电带载 + `servo_set_pulse` 限位 |

## 7. 预期效果（避免误判）

三路 IR 只能做到**区域级**跟随（左/中/右、上/下），表现为"一段一段挪过去"，不会像摄像头那样平滑。
对赛道"红外/距离传感器追踪桌面物品和手势"这条要求，区域级跟随是达标的。
