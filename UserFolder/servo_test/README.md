# 舵机调试与测试（servo_test）

TD1601 桌面机器人的两路舵机调试代码，集中在本文件夹。

## 0. ★ 最重要的结论：csi 通道号 ≠ 引脚手册的 PWM 通道号

`csi_pwm_out_config()` / `csi_pwm_out_start()` 的 `channel` 参数是 **「pinmap channel ÷ 2」**：

```
csi_ch = pinmap_channel / 2
```

**证据**：官方示例的 `board_config.h`

```c
#define EXAMPLE_PWM_CH_IDX    4             // csi 通道 = 4
#define EXAMPLE_PWM_CH        PIN31         // 引脚 PA31
#define EXAMPLE_PWM_CH_FUNC   PA31_PWM_CH8  // 引脚侧却是 PWM_CH8
```

`8 ÷ 2 = 4` ✓ —— 官方就是用 **csi 通道 4** 去驱动 **"第 8 号输出"** 的 PA31。

**对照 `components/chips/chip_td1601/v1.0/sys/devices.c` 的 `pwm_pinmap`（格式 `{port, pin, idx, channel, func}`）**：

| 引脚 | 引脚侧通道 | pinmap channel | **正确的 csi_ch** |
|---|---|---|---|
| PA0 | CH0 | 0 | **0** |
| PA1 | CH1 | 1 | 0 ← 与 PA0 **同对** |
| PA2 | CH2 | 2 | 1 |
| PA3 | CH3 | 3 | 1 |
| PA4 | CH4 | 4 | 2 |
| PA15 | CH4 | 4 | 2 |
| PA23 | CH0 | 0 | 0 |
| PA24 | CH1 | 1 | 0 |
| PA25 | CH2 | 2 | 1 |
| PA26 | CH3 | 3 | 1 |
| PA27 | CH4 | 4 | **2** ← 我们的 PITCH |
| PA29 | CH6 | 6 | **3** ← 我们的 YAW（2026-09 由 PA0 改来）|
| PA31 | CH8 | 8 | **4** ← 官方示例用的 |

**三个坑**：

1. 之前把 PA27 配成 `csi_ch 4`（照搬引脚手册的 CH4），实际写到了"输出 8/9"那对寄存器（PA31 那一组）→ **PA27 从来没有输出过**；
2. **`csi_ch` 相同的两个引脚属于同一对、共享一个 load 寄存器**：PA0 与 PA1 都是 `csi_ch 0`，波形必然同步 —— 这才是早期"PA0/PA1 波形同源"的真正原因（与短路、pad 映射无关），也意味着**它们不能当两路独立 PWM**；
3. **`csi_ch` 不能当数组下标用**：`csi_ch` 是 0 和 2（PITCH 是 2），但存放两路的数组只有 `[0]`、`[1]` 两个元素。`servo_range_test.c` 早前写 `s_ch[SERVO_PITCH_CH]` 就等于 `s_ch[2]` → 越界读 → 串口刷 **`CPU Exception: NO.5`（Load access fault）**。已引入 `IDX_YAW 0` / `IDX_PITCH 1` 专作数组下标，真实 `csi_ch` 存在结构体的 `.ch` 字段里传给驱动。**新增引脚/通道时，凡是数组下标一律用 IDX_\*，不要用 SERVO_\*_CH。**

> 驱动 `csi_pwm_out_start()` 内部 `wj_pwm_config_output_en(ch)` 置位 `PWMCFG` 的 `bit(2*ch)` / `bit(2*ch+1)`，在 `csi_ch = pinmap/2` 的规则下**是正确的**，无需任何手动补位。（此前基于误判加的 `servo_pwm_gate_fix()` 已删除。）

> - ✅ **已实测通过并固定为舵机控制端**：原为 **PA0 + PA27** 两路同时独立输出正常（2026-09）；**2026-09 为做 PCB 把 YAW 由 PA0 换到 PA29（排针外排 3 脚），PITCH 仍为 PA27** —— 换脚后须上板复验。PA27 的 `csi_ch` 是 **2**（pinmap 4 ÷ 2）—— 早前写成 4 时它一直没有波形（写到了 PA31 那一组寄存器）。
> - **PA31（pinmap 8 → `csi_ch 4`）已让出**，留给后续同步控制 / LCD 背光等用途。它与原 PA0 的组合此前已实测通过，需要时把 `servo_pins.h` 的 PITCH 那 5 行换成 `CH 4U` / `PIN31` / `PA31_PWM_CH8` / `"PA31"` 即可切回。
> - 两路 `csi_ch` 必须不同（同对的两个引脚共享 load 寄存器、输出必然同步）。

为什么不用 PA1 / PA2：

- **PA1**：与 PA0 同属 `csi_ch 0`（同对、共享寄存器），无法独立输出；
- **PA2**：LCD 片选（`src/video.c` 的 `CLR_CS1()/SET_CS1()`）。

**占用表（其余模块，舵机不碰）**

| 模块 | 占用引脚 |
|---|---|
| LCD | PA2 (CS)、PA3 (SCK)、PB4~PB7 (D0~D3)、PB10 (WAIT)、PB15 (RST)、PA31 (背光建议值) |
| 触摸 | PA8 (TP_SCL)、PA9 (TP_SDA) |

可用备选（引脚 / pinmap / csi_ch）：`PA0 (0→0)`、`PA4 (4→2)`、`PA5 (5→2)`、`PA6 (6→3)`、`PA7 (7→3)`、`PA24 (1→0)`、`PA25 (2→1)`、`PA26 (3→1)`、`PA30 (7→3)`、`PA31 (8→4)`。两路务必选 `csi_ch` 不同的。**其中底部排针可达的只有：外排 PA29(已用) / PA30、内排 PA28。**

## 4. MVP（`servo_mvp_test.c`）—— 建议先跑这个

三种模式，改 `MVP_MODE` 切换。**从最容易观察的模式 2 开始**：

| MVP_MODE | 内容 | 怎么观察 |
|---|---|---|
| **2** | **GPIO 慢方波**：PA0 每 500ms 翻转一次（1Hz，完全不经过 PWM）| **不需要示波器**：万用表直流档能看到 0V ↔ 1.8V 跳动（均值≈0.9V）；接 LED+1kΩ 会明显闪烁 |
| **1**（默认）| **正弦调制 SPWM**：载波 1kHz（周期 1000us），占空比在 5%~95% 之间按 16 点正弦表变化，每点 60ms → 约 960ms 一个正弦周期 | 示波器 **200ms/div** 看正弦包络；**200us/div** 看载波；引脚后串一个 RC 低通（1kΩ 串 + 100nF 到 GND）就是纯正弦波 |
| 0 | **官方 PWM 方波**：周期 30us、低电平 10us（≈33kHz，官方示例原样）| ⚠️ 时基必须给到 **10~20us/div**；若还停在 5ms/div 会糊成一片亮带，看起来就像"没有波形" |

| MVP_TARGET | 引脚 / 复用宏 | csi_ch | 用途 |
|---|---|---|---|
| 0 | PA0 / `PA0_PWM_CH0` | 0 | 原水平 YAW（2026-09 已换到 PA29，此项现仅作单路诊断）|
| 1 | PA27 / `PA27_PWM_CH4` | **2** | 我们的垂直 PITCH（注意是 2）|

## 5. servo_dual_test：双路回归验证（走 servo_core 控制层）

> ✅ **实测通过**：**PA29**（`csi_ch 3`，2026-09 由 PA0 改来）+ PA27（`csi_ch 2`）两路同时输出、各按自己的节奏变化、互不牵连。（原 PA0 + PA27 的组合亦已于 2026-09 验证。）

本测试特意**调用控制层 `servo_core`**（而不是自己直接操作 csi_pwm），一次同时验证三件事：

1. **控制层可用**：`servo_core_init()` + `servo_set_pulse()` 正常；
2. **限位钳制生效**：两路往复范围都在 `servo_core.h` 的实测限位内，全程不应有异响/顶极限；就算故意给超范围值也会被钳制并打印提示；
3. **两路独立**：两者的 `csi_ch` 不同（YAW=3 / PITCH=2），各走各的、互不牵连。

| 路 | 引脚 | csi_ch | 往复范围 | 步进节奏 |
|---|---|---|---|---|
| A | PA29 | 3 | 800 ~ 1500us | 每 500ms 走 20us |
| B | PA27 | 2 | 1200 ~ 1600us | 每 700ms 走 40us |

- **为什么能独立**：两者 `csi_ch` 分别是 3 和 2，**不在同一对**上，不共享 load 寄存器（同对的两个引脚才共享，比如 PA0/PA1 都是 `csi_ch 0`）
- 串口每步打印两路脉宽（如 `[dual] PA29(ch3)=1000us (5.0%)   PA27(ch2)=1300us (6.5%)`），便于对照
- 接上舵机可以看到两个舵机以**不同节奏、不同幅度**摆动
- 脉宽都在实测行程内，不会顶到机械极限（超了也会被 `servo_set_pulse()` 钳制）

**怎么看才算回归通过**

| 现象 | 结论 |
|---|---|
| 上电两路稳定停在中位、无嗡响 | ✅ 控制层回中正常 |
| 两路各按自己的节奏变 | ✅ 分立控制成立 |
| 串口**没有** `clamped` 之类被钳制的提示 | ✅ 限位设置合理（没超实际行程）|
| 一路变化时另一路跟着变 | ❌ 两路被耦合（同对/共享寄存器）→ 换到 `csi_ch` 不同的引脚 |
| 某一路完全不动 | ❌ 该引脚无输出 → 查接触 / 是否引出到可测位置 |
| 出现异响 / 顶死 | ❌ 某个范围值仍超实际行程 → 把对应的 MIN/MAX 再收一点 |

## 6. servo_range_test：命令与测极限流程

| 命令 | 说明 |
|---|---|
| `h` / `?` | 帮助 |
| `0` / `1` | 选通道：0 = 水平 PA29，1 = 垂直 PA27 |
| `+` / `+n`、`-` / `-n` | 脉宽增减（默认 20us），如 `+50` |
| `w<us>` | 直接设置脉宽，如 `w1500` |
| `c` / `b` | 当前通道 / 两路 回中位 |
| `z` | 把当前脉宽记为当前通道的新中位（中位标定） |
| `l<min>,<max>` | 设置当前通道软限位，如 `l800,1600`（PITCH 的实测行程）|
| `i` / `p` | 打印状态（含本次会话到达过的范围 `probed`） |

**测极限流程**：选通道 → 反复 `-` 逼近 → 出现异响/堵转立刻 `+` 退回一步并记录 → 换向再来一次 → 用 `i` 核对 `probed` → 用 `z` 定中位、`l` 设限位。
任何输入都会被钳到软限位与硬限位 `[200, 2700]us` 之间。

**实测记录表（2026-09 实填，已回填到 `servo_core.h` 的限位宏）**

| 自由度 | 引脚 | 中位 us | 行程范围 us | 备注 |
|---|---|---|---|---|
| 水平 YAW | PA29 | **1000** | **300 ~ 1700** | 对应本测试的通道 `0` |
| 垂直 PITCH | PA27 | **1100** | **800 ~ 1600** | 对应通道 `1` |

> 2026-10-31 曾按"手动逐点试"收窄到 YAW 960 / 300~1440、PITCH 800~1320：
> 手动单点确实只能到那儿，但**动作库用不到那么远** —— 强情绪下幅度 ×1.38 之后
> YAW 最大落点 1497、PITCH 1398，全被新限位挡住 → 动作顶死、堵转、卡顿。
> 已回退到上表。**要收限位，必须同时按比例收动作幅度**，否则就是把动作顶在墙上跑。

角度换算参考：标准舵机 500~2500us 对应 0~180°，约 **11.1us/°**；历史实测也出现过约 **5.6us/°** 的舵机，以实测为准。

## 7. servo_motion_test：动作库测试台（串口直接播动作）

> **2026-10-31 改版**：原来的「正弦 / 扫掠 / 8 字」运动状态测试已整体替换。
> 现在这个入口**直接播放 `movements/` 里的动作库**，走的是正式固件同一套
> `moves_* → apply_off → servo_set_pulse` 路径 —— 限位、限速、总线仲裁全都一致，
> 所以这里能跑通，正式固件里就一定跑得通。调好动作再回 `TEST_ENTRY=4` 验收。

入口：`src/main.c` 的 `#define TEST_ENTRY 5`（只初始化舵机 + 动作库 + console，
屏幕/触摸/UI 都不初始化，所以不受刷屏干扰）。

| 命令 | 说明 |
|---|---|
| `h` / `?` | 帮助 |
| `i` | 状态（增益、两路脉宽、是否在播放）|
| `l` | 列出所有动作 id 与变体数 |
| `p<id>` | 播放该动作（随机变体），如 `p4` |
| `p<id>.<v>` | 播放指定变体，如 `p4.1`（v 从 0 起）|
| `d` | 演示：从 IDLE 到 SLEEP 依次播一遍 |
| `g<amp>,<spd>` | 设调制增益（千分比 600~1500），如 `g1200,1400` |
| `r` | 增益复位 1000,1000 |
| `s` | 中断当前动作（停在原地）|
| `0` / `1` | 选通道（手动定位用）|
| `w<us>` / `j<us>` | 手动平滑 / 跳变到某脉宽 |
| `+` / `-` | 微调 20us |
| `c` / `b` | 当前 / 两路 平滑回中位 |

**播放期间任意键都会立刻打断**（不用干等 7 秒），打完的那一行会在动作停下后自动执行，
所以动到一半直接敲 `p5` 切下一个也行。实现上靠 `moves_set_tick_hook()` 在动作的
20ms 钩子里轮询串口，和 `emotion_fsm.c` 的做法一致。

动作 id 见 `moves.h` 的 `move_id_t`（0=IDLE 1=HAPPY 2=EIGHT 3=SAD 4=ANGRY
5=SURPRISED 6=LOVING 7=BORED 8=SLEEP），串口发 `l` 也能列出来。

典型验收流程：
1. 上电两路回中位、无异响
2. `d` 全播一遍，记下哪个动作有嗡响/卡顿
3. `g1200,1400` 把增益拉到正式固件的上限，再播那些动作 —— 能过才算真的没问题
4. 串口若刷 `[mv] CLIP: ...`，说明该动作幅度顶到实测限位，看括号里的 ok 范围就知道超多少

## 9. 代码要点（复用备忘）

- 引脚复用：`csi_pin_set_mux(port, pin, func)`，参数用 `servo_pins.h` 的宏（`func` 是引脚侧复用值，如 `PA27_PWM_CH4`）
- 初始化（都在 `servo_core_init()` 里做一次）：`csi_pwm_init(pwm, 0)` →
  `csi_pwm_out_config(pwm, csi_ch, 20000, pulse_us, PWM_POLARITY_HIGH)` → `csi_pwm_out_start(pwm, csi_ch)`（**只在这一处 start**）
- **改脉宽：只写 compare**（`wj_pwm_counter_write_compare_a_ch/_b_ch`），**不要再 `stop → config → start`** ——
  那会每步关一下输出使能：两路关断时刻不同 → 两轴不同步、脉冲可能被截断（2026-09 的修正，详见 `servo_core.c` 头部）
- **`csi_ch = pinmap_channel / 2`**（第 0 节），同一个 `csi_ch` 的两个引脚不能同时当两路用
- 驱动限制：`csi_ch` 必须 `< 6`；周期与脉宽受 16bit 计数能力约束
- 寄存器回读（仅调试用）：`wj_pwm_counter_read_compare_a_ch(base, ch)`，换算 `cmp = 3.1875 × (20000 − pulse)`（例：1000us→60562、1500us→58968）；`HANDLE_REG_BASE` 宏必须传**指针变量**
