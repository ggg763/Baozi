# movements —— 情感状态对应的舵机动作库

把"情感状态 → 舵机动作"的代码集中在这里，**每个状态一个文件**，动作之间互不干扰、便于单独调。

## 文件结构

| 文件 | 作用 |
|---|---|
| `moves.h` | 动作 ID、轨迹原语接口、**变体池接口**、主变体①的可调参数（`IDLEP1/2/3_*` · `HAPPY_*` · `EIGHT_*` · `SAD_*` · `ANGRY_*` · `SURPRISED_*` · `LOVING_*` · `BORED*_*` · `SLEEP_*`）；**变体②③的参数在各动作文件顶部**（见下）|
| `moves.c` | **基础库**：轨迹插值（`move_line` / `move_to` / `move_by` / `move_center` / `move_hold`）+ 曲线轨迹（`move_figure8`）+ 动作注册表 + **变体池（随机呼出）** + 播放引擎 + 可打断 + **调制增益** + **播放期 tick 钩子** |
| `moves_idle.c` | **待机（IDLE）**：3 个变体 —— 缓慢环视 / 远望俯视 / 扁 8 字巡游 |
| `moves_happy.c` | **开心（HAPPY）**：3 个变体 —— 欢快摇晃 / 点头雀跃 / 绕圈庆祝 |
| `moves_eight.c` | **八字环绕（EIGHT）**：脖子画横 8 字 ∞（**暂不做变体**：8 字有堵转待定位，先不叠负载）|
| `moves_sad.c` | **难过（SAD）**：3 个变体 —— 垂头丧气 / 长叹 / 无力摇头 |
| `moves_angry.c` | **生气（ANGRY）**：3 个变体 —— 甩头 / 瞪着你 / 生闷气 |
| `moves_surprised.c` | **惊讶（SURPRISED）**：3 个变体 —— 猛抬头 / 吓一跳 / 疑惑定住 |
| `moves_loving.c` | **爱意（LOVING）**：3 个变体 —— 温柔歪头 / 轻轻蹭 / 慢慢看你 |
| `moves_bored.c` | **无聊（BORED）**：3 个变体 —— 歪头发呆 / 垂头发呆 / 东倒西歪 |
| `moves_sleep.c` | **睡眠（SLEEP）**：3 个变体 —— 垂头呼吸 / 侧头睡 / 浅眠 |
| `moves_demo.c` | 演示入口 `moves_demo()`：循环播 `DEMO_MOVE` 指定的动作（已被 `emotion/emotion_fsm.c` 取代，保留作单动作自测）|

## 身体模型：两个舵机就是机器人的"脖子"

| 轴 | 引脚 | 身体语义 | 拟人说法 |
|---|---|---|---|
| YAW（水平）| PA29（csi ch3；2026-09 由 PA0 换脚）| 脖子**左右转** | 转头 / 摇脑袋 / 左右张望 |
| PITCH（垂直）| PA27（csi ch2）| 脖子**抬头/低头** | 点头 / 抬头看 / 低头 |

> 所以写动作时直接用"转头多少 + 点头多少"的思路思考：比如"左转 300、稍稍抬头 25"就是
> `move_to(-300, +25, 4000)`（从当前位置平滑走过去）。以后加了别的执行器（底座旋转、手臂），再往这个模型里扩展。

## 坐标约定（重要）

动作代码**只写"相对中位的偏移 us"**，不关心绝对脉宽 —— `moves.c` 会加上 `servo_test/servo_core.h` 里的实测中位，并走 `servo_set_pulse()` 的限位钳制。

| 方向 | 含义（实测）|
|---|---|
| `+yaw_off` | 脉宽增大 → **右转** |
| `-yaw_off` | 左转 |
| `+pitch_off` | 脉宽增大 → **抬头** |
| `-pitch_off` | 点头（低头）|

中位 / 限位（2026-09 实测）：YAW 中位 1000us（300~1700）、PITCH 中位 1100us（800~1600）。
**动作幅度写超了也不会顶极限**（会被钳制），但还是尽量留在行程内。

## 变体池：同一状态多个动作，随机呼出（2026-09 新增）

**要解决的问题**：同一个动作一遍遍循环播，几十秒就能看出"机械感"（人一眼就知道它在放同一段动画）。

**做法**：一个状态可以挂 1~`MOVE_MAX_VARIANTS`（当前 3）个**变体**，每个变体本身就是一条
**15~23s 的多段长链**（幅度、方向、停留都不同）；呼出时随机挑一个，并且**不与上一次相同**。

| 接口 | 用途 |
|---|---|
| `moves_play_variant(id)` | **随机**播一个变体（不与上次相同）—— 正式状态机用这个 |
| `moves_play_variant_at(id, n)` | **固定**播第 n 个变体 —— 调参时反复看同一个用 |
| `moves_play_once(id)` | 固定播**主变体**（= 第 0 个）|
| `moves_variant_count(id)` | 该状态有几个变体（1 = 只有主实现）|
| `moves_last_variant(id)` | 上次随机到的变体下标（0 起）|
| `moves_rand()` | 小伪随机（LCG）；动作内部想加"轻微变化"时可用 |

哪些状态有变体（2026-09 已全铺开）：**除 `MOVE_EIGHT` 外的 8 个状态都挂满 3 个变体** ——
IDLE（缓慢环视 / 远望俯视 / 扁 8 字巡游）、HAPPY（欢快摇晃 / 点头雀跃 / 绕圈庆祝）、
SAD（垂头丧气 / 长叹 / 无力摇头）、ANGRY（甩头 / 瞪着你 / 生闷气）、
SURPRISED（猛抬头 / 吓一跳 / 疑惑定住）、LOVING（温柔歪头 / 轻轻蹭 / 慢慢看你）、
BORED（歪头发呆 / 垂头发呆 / 东倒西歪）、SLEEP（垂头呼吸 / 侧头睡 / 浅眠）。

`MOVE_EIGHT` 暂时保持 `count = 0`（8 字有堵转待定位，先不给它叠负载）——
`count = 0` 会自动退回主实现，行为与以前完全一样。

> ⚠️ 随机用的是固定种子的 LCG：序列本身是确定的，但因为每个变体时长不同、每轮推进的步数不同，
> 加上"不与上次相同"的规则，实际观感足够不机械。将来若要更强的随机性，把种子混入自由运行计数器的低位即可。

## 调制增益：连续情绪状态 → 动作幅度/速度

固定轨迹负责**怎么动**（波形、节奏、姿态语义，人手调优），增益负责**动多大、动多快**（由状态机按
连续情绪状态实时给出，千分比 1000 = 原样）：

- `moves_set_gain(amp, spd)` —— amp 缩放目标偏移、spd 缩放时间；作用于 `move_to` / `move_by` / `move_center` / `move_figure8`
  （底层 `move_line` / `move_hold` **不缩放**，保留精确落点与留白语义）；
- `MOVE_AMP_BASE`（在 `moves.h`，当前 **1200**）—— **整体幅度基准**：2026-09 上机发现所有动作幅度偏小，
  于是统一放大 20%。放在动作库这一层（而不是逐个改动作参数）的好处：manual / fsm / demo **全路径一起变大**、
  各动作之间的相对大小不变，以后想再整体调也只改这一行。
  **实际输出偏移 = 动作文件里的偏移 × MOVE_AMP_BASE/1000 × amp/1000**；
- `moves_set_tick_hook(fn)` —— 动作库每走一个 20ms 插值步就回调一次，让状态机在**动作播放期间**也能收串口命令并立即打断。

## 怎么新增一个状态动作

1. **新建 `moves_<状态>.c`**，实现 `void moves_<状态>_run(void)`：
   ```c
   #include <stdint.h>
   #include "moves.h"

   void moves_hungry_run(void)
   {
       move_center(300);                      /* 先回中 */
       if (moves_interrupted()) { return; }
       move_to(0, -100, 400);                 /* 低头 */
       if (moves_interrupted()) { return; }
       move_to(-200, -60, 1500);              /* 往左慢慢摆 */
       if (moves_interrupted()) { return; }
       move_to(+200, -60, 1500);              /* 往右（行程 2n）*/
       if (moves_interrupted()) { return; }
       move_center(400);
   }
   ```
   > - 每个 `move_to()` / `move_hold()` 之后都查一次 `moves_interrupted()`，这样状态切换能立即打断动作。
   > - **用 `move_to()` 写目标位置**（起点自动取当前位置），不要用 `move_line()` 手写起点 —— 容易与上一段对不上。
   > - **来回摆动要写在"两侧之间"**：摆幅 n 是从中心到一侧的距离，从一侧(+n) 摆到另一侧(-n) **行程是 2n**；
   >   若某一段从中心出发，那一段只走了 n，整段动作就会"第一下短、后面长"。
   > - **慢动作要把时间写够**：`move_to(x, y, ms)` 的 ms 是这一段的总时长（20ms 一步插值），
   >   "缓慢"靠的是把 ms 放大（比如 4000），而不是把幅度缩小。
   > - **快速往复动作要防"没到位就反向"**（2026-09 踩过）：舵机开环，脉宽一换向就反向，
   >   上一段没走完就换向会让**实际摆幅被削平** —— 现象是"幅度看着很小"，而根因是速度。
   >   经验：需求速度 = (2×摆幅 × MOVE_AMP_BASE/1000) / 段长ms **别超过 5us/ms**
   >   （9g 舵机极限约 6.7us/ms），并在每个极点加一次 `move_hold(30~60ms)`
   >   （各动作里的 `*_SETTLE_MS`）让舵机先把这一侧咬住再反向。
   >   排查手法：同一动作 `gain 1000 500`（放慢一倍）再看 —— 摆幅明显变大 = 速度问题，加时间即可。

2. **在 `moves.h` 的 `move_id_t` 里加一项**：`MOVE_HUNGRY,`

3. **在 `moves.c` 的 `s_moves[]` 表里登记**：
   ```c
   { "hungry", moves_hungry_run },
   ```
   （并在文件上部加 `extern void moves_hungry_run(void);`）

4. 记得把新 `.c` 加进 `baozi/package.yaml` 的 `source_file`。

## 怎么给已有状态加一个变体（降低重复感）

1. 在**该状态的同一个文件**里写实现函数（例如 `moves_idle.c` 里加 `moves_idle_v4_run()`），
   参数另起一组宏写在**该文件顶部**（前缀如 `IDLEP4_*`）——【2026-09 约定】主变体①的参数留在
   `moves.h`，变体②③… 的参数就近放在动作文件顶部（否则 `moves.h` 会被几十组宏撑爆）；
2. 在 `moves.c` 的变体池里登记：给 `s_idle_vars[]` 加一项，并把 `s_variants[MOVE_IDLE].count` 从 3 改成 4；
3. **注意容量上限 `MOVE_MAX_VARIANTS`（当前 3）**：不够就把它加大（数组是定长的）；
4. 新变体尽量与已有变体"性格不同"（不同的方向顺序、不同的幅度层次、是否用曲线轨迹），否则随机也看不出区别。

## 调试方式

- **串口交互测试**（推荐）：烧 `UserFolder/test/emotion_test.c` 的入口 `emotion_test()`，
  命令表见 `doc/README.md` §4.2（`list` / `play <id> <1..N>` / `gain amp spd` / `state` …）；
- 每个状态 3 个变体（`MOVE_EIGHT` 除外）：连续看几轮会随机换一条，不会一直是同一段动作；
- 单独调某个动作：改 `moves_demo.c` 顶部的 `DEMO_MOVE` 再烧录；
- 调幅度/速度：改 `moves.h` 里对应的参数宏（**变体②③ 的参数在各自的 `moves_<状态>.c` 顶部**）；
- 想看某个偏移对应的实际位置：用 `servo_test/servo_range_test` 先试出脉宽，再换算成偏移。
